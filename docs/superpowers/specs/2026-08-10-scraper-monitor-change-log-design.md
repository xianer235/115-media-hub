# 刮削精准同步日志明细设计

## 背景与目标

刮削操作驱动的精准 STRM 同步目前只在监控日志中输出生成数、删除数和失败数，无法直接确认哪些本地 STRM 被删除或生成。本设计补充可信的本地变更明细，同时避免文件夹改名、移动或复制时把整个已知索引展开成大量日志。

日志用于说明已经提交成功的本地结果，不用于展示动作意图。共享 STRM 未实际删除、已有 STRM 内容相同而未重写、事件失败或事务回滚时，不得输出对应的成功明细。

## 展示规则

### 单文件操作

单文件新增、删除、重命名和移动全部记录本地 STRM 相对路径。路径包含 `.strm` 后缀，不显示 `/app/strm` 绝对路径、115 远端路径或播放 URL。

同一个文件的重命名或移动按实际执行顺序成对显示：

```text
删除 STRM: 媒体库/一级/二级/旧名称.mkv.strm
生成 STRM: 媒体库/一级/二级/新名称.mkv.strm
```

批量文件操作按事件 ID 顺序输出，每个文件的删除和生成保持相邻。纯删除只显示删除行，纯新增只显示生成行。

### 文件夹操作

文件夹重命名、移动和复制不展开内部文件，只记录本地文件夹映射和实际 STRM 数量：

```text
文件夹变更: 媒体库/一级/旧目录 -> 媒体库/一级/新目录（删除 120，生成 120）
```

文件夹操作按实际范围使用明确动词：同一监控任务内的重命名或移动显示“文件夹变更”，复制显示“文件夹复制”，移出或删除显示“文件夹删除”，移入或创建显示“文件夹新增”。只有旧、新两侧都能映射到该任务的本地路径时才显示箭头；单侧操作只显示存在的一侧。括号中的删除数和生成数始终是实际物理 STRM 变化数。

未知或不完整文件夹完成已知索引同步后，沿用现有“需手动监控”状态和汇总，不把未知内容写成已同步。

文件夹路径同样只使用本地相对路径，不带 `.strm` 后缀。路径中的换行符必须在格式化时替换为空格，避免一条路径伪造成多条日志。

## 数据流与边界

`app/services/monitor_changes.py` 在每个事件执行期间收集有序的日志候选项：

- `_delete_unreferenced_strm_file` 只有真正删除物理 STRM 时记录删除项；其他监控任务仍引用同一输出时不记录。
- `_write_strm_file` 只有真正创建或改写物理 STRM 时记录生成项；内容未变化时不记录。
- 单文件事件保存有序的删除/生成项；文件夹事件只保存目录映射和计数，不保存内部文件明细。
- 候选项属于事件事务的一部分。数据库提交失败或本地操作异常时，现有 journal 恢复 STRM，候选项随事件失败一起丢弃。
- 每个事件提交成功后，才把候选项追加到 `process_monitor_change_events` 的返回结果；跨事件顺序与数据库读取顺序一致。

`app/services/monitor.py` 只负责格式化并写入监控日志：先输出成功事件的明细，再输出现有同步汇总和失败事件。处理层不直接依赖日志模块，日志写入失败也不反向改变已经提交的 STRM 和索引。

返回结果新增内部字段，不修改持久化事件表和公开状态接口：

```json
{
  "change_details": [
    {
      "kind": "file",
      "changes": [
        {"action": "delete", "path": "媒体库/一级/二级/旧名称.mkv.strm"},
        {"action": "generate", "path": "媒体库/一级/二级/新名称.mkv.strm"}
      ]
    },
    {
      "kind": "folder",
      "operation": "move",
      "old_path": "媒体库/一级/旧目录",
      "new_path": "媒体库/一级/新目录",
      "deleted": 120,
      "generated": 120
    }
  ]
}
```

该字段只在当前任务进程内传递，不写入数据库，不进入监控状态轮询接口。

## 错误与规模控制

- 单文件批量操作逐文件完整输出，不截断；这是用户需要核对的直接变更清单。
- 文件夹操作无论包含多少已知文件都只输出一条目录摘要，避免大型目录产生数千行日志。
- 失败事件仍沿用现有“变更事件失败，已保留重试”日志，不输出其候选成功明细。
- 某个事件需要重试且后续成功时，只在最终成功的那次任务日志中输出一次明细。
- 日志明细只反映物理 STRM 文件变化；索引更新但物理文件被共享引用或内容未变化时，汇总计数和明细都保持现有实际变更口径。

## 测试与验证

定向测试覆盖：

- 三个二级目录文件批量改名产生六行严格交替的删除/生成日志，路径为本地相对 STRM 路径。
- 纯新增和纯删除各只产生对应的一行。
- 共享 STRM 未实际删除时不产生删除明细。
- STRM 内容相同未重写时不产生生成明细。
- 文件夹重命名、移动、复制和删除只输出目录摘要，不展开内部文件。
- 本地写入失败或数据库提交失败并回滚时不输出成功明细，重试成功后只输出一次。
- 路径换行符被替换，不产生伪造日志行。

本次实现按变更风险运行 5 项精准同步定向测试（批量三文件改名、共享 STRM、写入失败回滚、文件夹改名和日志顺序），并通过项目 `compileall`、`version.json` JSON 解析及 `git diff --check`。本次没有 JavaScript 改动，因此不运行 `node --check`；按用户要求也未重复完整测试套件。Docker 可用时仍应重建当前源码，真实 115 验证限定在用户明确允许的小目录中。
