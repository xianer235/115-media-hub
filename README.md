# 115 Media Hub

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Release](https://img.shields.io/github/v/release/xianer235/115-media-hub)](https://github.com/xianer235/115-media-hub/releases/latest)
[![Docker Pulls](https://img.shields.io/docker/pulls/xianer235/115-media-hub)](https://hub.docker.com/r/xianer235/115-media-hub)
[![Stars](https://img.shields.io/github/stars/xianer235/115-media-hub)](https://github.com/xianer235/115-media-hub/stargazers)

`115 Media Hub` 是一个基于 FastAPI 的媒体自动化管理面板：把网盘转存、115 网盘 `.strm` 生成、影视订阅追更、文件管理与跨网盘复制收在同一个后台，让 Jellyfin / Emby / Plex 直接播放网盘里的片子。

它适合「电影存在 115、剧集靠订阅追更、媒体库交给 Jellyfin/Emby/Plex」这种自部署场景；不想要网盘客户端、也不想手动搬文件的人用它最省事。

> **本项目采用 MIT 许可证免费开源，所有功能都可以直接使用，没有付费版，也不需要购买任何授权。** 如果你在别处看到「专业版」「授权码」「激活」之类的说法，那不是本项目提供的。

## 功能总览

| 模块 | 作用 |
| --- | --- |
| 资源中心 | 同步 TG 公开频道、接入 PanSou 盘搜、手动粘贴资源，支持 magnet / ED2K / 直链与各网盘分享链接入库 |
| 影视订阅任务 | 电影 / 剧集按名称自动找资源入库，支持周期调度、评分阈值、质量偏好、TMDB 绑定与追更，可按季订阅 |
| 文件夹监控任务 | 扫描网盘目录生成 / 同步 `.strm`，支持手动、定时、Webhook 触发与局部刷新；只扫描，不整理 |
| 接收夹 | 分类前的中转文件夹：磁力、转存、手动保存先丢进来，自动识别影视类型后搬进对应分类目录 |
| 目录树任务 | 调官方「导出目录树」接口，按 sha1 增量更新 `.strm`，支持全量重写；适合大库一次性建库 |
| 文件管理 | 网盘浏览与复制 / 移动 / 重命名 / 删除，**跨网盘复制**、TMDB 识别绑定、批量重命名刮削 |
| Seerr 点播 | 把面板当成 Radarr / Sonarr，家人在 Seerr 点一下即自动建订阅任务；Emby 兼容桥可让 Seerr 复用极影视的库索引 |
| 命令行（CLI） | 宿主机命令行客户端，通过面板 API 完成搜索 / 订阅 / 转存 / 监控 / 刮削 / STRM |
| 企业微信通知 | 订阅成功、监控生成、跨盘复制等事件推送，机器人与应用两种通道，各事件独立开关 |
| 115 每日签到 | 手动或定时签到，页面顶部展示状态 |

**支持的网盘**：`115` / `夸克` / `天翼云盘` / `123云盘` / `阿里云盘`，通过 Cookie 或官方授权驱动；115 支持内置扫码登录、磁力离线与 `.strm` 生成，阿里云盘支持官方 OAuth 扫码，其余网盘以分享 / 链接入库为主。

**资源来源**：TG 公开频道、PanSou 盘搜、手动粘贴；**元数据**：TMDB（可自定义 API 与图片地址）。

## 部署

### 前置要求

- Docker 24+ 与 Docker Compose v2（`docker compose`，不是老的 `docker-compose`）
- 镜像只提供 `linux/amd64`；ARM 设备（树莓派、部分 NAS）请用下面「方式 B」本地构建
- `config` 目录至少留 1GB（数据库、Cookie、缓存）
- 一个 115 账号（其他网盘可选）；服务器能访问 TMDB / Telegram（都不通的话后面在「网络代理」里配）

### 方式 A：拉官方镜像（推荐）

把下面内容存成 `docker-compose.yml`：

```yaml
services:
  115-media-hub:
    image: xianer235/115-media-hub:latest
    container_name: 115-media-hub
    restart: unless-stopped
    ports:
      - "18080:18080"
    volumes:
      - ./strm:/app/strm
      - ./config:/app/config
      - ./logs:/app/logs
    environment:
      - TZ=Asia/Shanghai
```

```bash
docker compose up -d
```

### 方式 B：用仓库自带 compose 本地构建

```bash
git clone https://github.com/xianer235/115-media-hub.git
cd 115-media-hub
cp .env.example .env      # 按需改端口、目录、时区
docker compose up -d --build
```

**两种方式别混用**：方式 A 的默认目录是 `./strm` `./config` `./logs`；仓库 `compose.yml` 读 `.env`，默认落在 `./data/strm` `./data/config` `./data/logs`。从 A 切到 B（或反过来）前，先把旧目录里的数据搬过去，否则看起来像「配置全丢了」。

| | 方式 A 拉镜像 | 方式 B 本地构建 |
| --- | --- | --- |
| 镜像来源 | Docker Hub 官方镜像 | 本地构建（可用 ARM） |
| 默认数据目录 | `./config` `./strm` `./logs` | `./data/*`（`.env` 可改） |
| 升级命令 | `docker compose pull && docker compose up -d` | `git pull && docker compose up -d --build` |
| 适合 | 大多数用户 | ARM 设备、想改代码 |

### 首次访问

- 打开 `http://服务器IP:18080`
- 默认账号 `admin` / 密码 `admin123`
- **登录后第一件事**：到「参数配置 → 系统与存储 → 账号、签名密钥与油猴脚本」改掉默认密码，顺手生成一个签名密钥（Webhook 要用）

### 持久化目录

| 路径 | 说明 |
| --- | --- |
| `/app/config/settings.json` | 全部设置（含网盘 Cookie，敏感） |
| `/app/config/data.db` | SQLite：任务状态、命中记录、复制断点 |
| `/app/config/trees` | 目录树缓存与中间文件 |
| `/app/config/.session_secret` | 登录会话密钥（丢了只是所有人重新登录） |
| `/app/logs/*.log` | `task.log` / `monitor.log` / `subscription.log` |
| `/app/strm` | 生成的 `.strm` 播放文件，可随时重建 |
| `/app/storage` | 跨盘复制暂存区（可选，不挂就落在 config 卷里） |

### 升级

```bash
# 方式 A
docker compose pull && docker compose up -d

# 方式 B
git pull && docker compose up -d --build
```

想回滚就把 `image:` 的 `:latest` 换成具体版本号（每个版本都推了 tag，例如 `xianer235/115-media-hub:0.16.18`）再 `docker compose up -d`。升级不会动 `config`，任务、订阅、Cookie 都保留。

### 备份与恢复

只需要备份 `config` 目录（设置、数据库、Cookie 全在里面）；`strm` 可以让任务重建。

```bash
docker compose stop
tar -czf 115hub-config-$(date +%F).tar.gz ./config      # 备份
# 恢复：把压缩包解回 ./config，再 docker compose start
docker compose start
```

### 改端口 / 看日志

- 改端口：方式 A 改 `ports` 左边（`"8080:18080"`）；方式 B 改 `.env` 的 `MH_PORT`，然后 `docker compose up -d`
- 容器日志：`docker compose logs -f --tail 200`
- 业务日志：宿主机 `logs/` 目录下的三个 `.log`

## 首次配置（5 分钟）

1. **授权网盘**：打开「参数配置」→「网盘与账号」→ 115 那栏点「扫码登录」，用微信小程序或电视端扫码（自动写入 Cookie，不会挤掉你手机上已登录的设备）；也可以粘贴 Cookie。其他网盘按需同法。
2. **配播放地址**：参数配置 →「播放与点播」→ 填 `STRM 对外访问地址`（例如 `http://192.168.1.20:18080`），确认「扫描后缀名」符合你的片源类型。
3. **建第一个任务**（二选一）：
   - 库大、更新少 → 「目录树任务」新增，选 115 文件夹后「生成并同步」
   - 已有固定目录、只想持续补新 → 「文件夹监控任务」新增，选扫描目录与 `strm` 输出目录
4. **验证**：到宿主机 `strm` 目录看有没有 `.strm` 文件；用文本编辑器打开一个，里面应该是一条 115 播放地址。
5. **接媒体服务器**：把 `strm` 目录挂给 Jellyfin / Emby / Plex，媒体库路径指向它，扫库即可播放（播放由播放器直接读 115 直链，不占服务器带宽）。

可选能力：TMDB 识别（元数据与识别）、PanSou 盘搜、企业微信通知（通知推送）、115 签到、Seerr 点播（见 [Seerr 对接教程](docs/seerr-setup-guide.md)）、油猴脚本（见 [浏览器辅助脚本](docs/browser-script.md)）。

## 怎么选任务

| 需求 | 推荐方式 |
| --- | --- |
| 媒体库很大、更新不频繁 | `目录树任务` |
| 已有固定目录，想持续补新内容 | `文件夹监控任务` |
| 想按影片 / 剧集名称自动找资源 | `影视订阅任务` |
| 想把 115 转存、磁力离线、刷新串起来 | `资源中心 + Webhook + 文件夹监控任务` |
| 不想每次挑分类 | `接收夹` |
| 需要批量重命名刮削网盘文件 | `文件管理` |
| 想把一个网盘的文件搬到另一个网盘 | `文件管理`（复制 → 切到目标网盘 → 跨网盘粘贴）或 `任务 → 跨盘复制` |

> **接收夹**是「分类前的中转文件夹」，也是一个可选的**便捷入口**：磁力、转存、手动保存先统一丢进去，自动识别是电影还是剧集后搬进同盘分类目录。它**不是强制流程**——给电影、剧集各建一个监控任务、直接推到分类目录的老用法完全保留。115 的接收夹和普通监控任务共用同一个 Webhook 签名密钥，只是收到请求后的处理流程不同。

## 常见故障排查

| 现象 | 处理 |
| --- | --- |
| 启动报端口被占用 | 换端口：方式 A 改 `ports` 左边，方式 B 改 `.env` 的 `MH_PORT`，再 `docker compose up -d` |
| 容器起来了但页面打不开 | `docker compose ps` 看是否 `Up`；`docker compose logs --tail 200` 看报错；确认防火墙 / 安全组放通端口 |
| 换 compose 文件后「配置全丢了」 | 两种方式的默认数据目录不同（`./config` vs `./data/config`），把旧目录搬过去再启动 |
| 容器反复重启 | `docker compose logs -f` 看第一段异常；多半是目录权限或磁盘满 |
| 115 提示 Cookie 失效 / 风控 | 参数配置 →「网盘与账号」重新扫码；同时把「115 API 最小间隔」调大（默认 0.35 秒） |
| 扫码成功但任务仍报未登录 | 扫码后要点「保存全部配置」；确认服务器时间准确（偏差大会导致签名失败） |
| 登录提示 401 / 账号密码错 | 默认是 `admin` / `admin123`；改过密码就用新密码。忘了密码可停容器后改 `config/settings.json` 的账号密码字段 |
| ARM 设备拉不到镜像 | 官方镜像只有 `linux/amd64`，用仓库 `compose.yml` 本地构建（方式 B） |
| 连不上 TMDB / Telegram | 参数配置 →「网络代理」填 HTTP 代理；TG 同步线程数调低 |
| Seerr 连不上面板 | Docker Desktop 用 `host.docker.internal`；Linux / NAS 填宿主机局域网 IP。Root Folder 选 `/` |
| 生成了 STRM 但媒体库看不到 | 确认 `strm` 目录挂给了媒体服务器、媒体库路径指向它、扫描已完成 |
| 媒体库能看到片子但播放失败 | 检查「STRM 对外访问地址」是否填成媒体服务器能访问的地址；`.strm` 里应是 115 直链 |

## 近期更新

当前版本见 [`version.json`](version.json)，完整历史见 [`CHANGELOG.md`](CHANGELOG.md)。

- **0.16.18**：文件管理「查重」以前只能勾一个文件夹，勾第二个按钮就灰了；打开后结果面板还夹在勾选栏和文件列表中间，面板一高列表就被压成两三行。现在可以一次勾 1~20 个条目——文件夹扫它自己（含子目录），文件扫它所在目录，同一目录只扫一次。查重打开后是独占视图，文件列表和勾选栏收起，结果区吃满整块面板，右上角「退出查重」（Esc 也行），退出后勾选还在。多个目录一起扫时结果不乱串：不同目录下都叫 `某剧/Season 01` 的文件不会并成一组，同一个文件也不会算两遍。
- **0.16.17**：集数识别补了一档兜底，认 `[组名][片名][05][1080P][BDRip]…` 这种发布组命名。以前这类文件名一个数字都认不出来（去分隔符后是 `DBDRawsBleach...051080P...`），跨盘补源会直接把它当「认不出集数」跳过，日志只写「没复制」，看着像没资源。现在会取文件名里唯一一个「纯数字方括号组」当集号，`[1080P]`、`[x265]`、`[FLAC]` 这类标签不会误认，年份和裸分辨率也排除；出现两个以上数字组（分段、合集）就放弃识别而不是乱猜。订阅补源的缺集判定、目标目录已有集扫描、文件管理「批量整理」都走同一个入口，一处改完三处生效。
- **0.16.16**：订阅任务编辑弹窗重排。原来 26 个字段平铺在一个滚动列表里，必填的「保存目录」排在第 12 位，改一个已有任务要滚八到十屏；现在常显卡只留类型/网盘/年份、影视名称、保存目录、TMDB 绑定和季数，其余按用途收进六个折叠分区（匹配与过滤、入库后整理、跨盘补源、固定分享链接、自动查询时段、高级扫描参数），折叠头右侧常显当前配置摘要，收起也知道配了什么。季数加了 TMDB 季表下拉，选季自动带出这一季的集数（数字框保留，季表不全时仍能手填）。电影订阅不再被挡住「入库后整理」，可以按「片名 (年份)」自动改名。另外修了推荐页加载时分类开关被挤到左边、加载完又弹回的问题。
- **0.16.15**：修两处手机端可用性。「扫描链接」弹窗一键粘贴几十行链接时，光标已经在末尾但画面还停在开头（浏览器只移动光标、不滚视口），现在会跟着滚过去，手动点选也有兜底；任务中心切到「跨盘复制」后当前类型标签不再变灰。另外手机端推荐页的搜索条回到一行——搜索框变长，电影/剧集分类下拉缩到只占文字宽度，不再比搜索框还长。
- **0.16.14**：修 0.16.13 的 CI 失败——测试用了 Python 3.12 已删除的 `check_hostname` 构造参数，本机 3.9 跑得通、CI 直接报错，镜像因此没构建出来。功能本身没问题，只改了测试，并加了一条守卫防止再写回去；同时升级 CI 的两个 action，消掉 Node 20 弃用警告。
- **0.16.13**：剧集详情现在能看出「库里有哪几季」。极影视把一季存成一个独立条目、多季共用同一个 TMDB 编号，旧逻辑去重后整部只剩一句「已有」；现在刷新库存会额外拉一遍季，详情里逐季显示绿色 `✓ 12 集`（全有）、`库中 8/12 集`（部分）或不打勾（没有），顶部写「已有 3/13 季」。只做到季，单集追更仍交给订阅任务。
- **0.16.12**：极影视接入说明补了一条——影视文件夹里**最好不要放 NFO**。判重只认条目上的 TMDB ID，而大量 NFO 只有片名和年份、没有 TMDB 编号，极影视以 NFO 为准就不再联网识别，结果推荐页不标「已有」。必须用 NFO 时至少要写 `<uniqueid type="tmdb">12345</uniqueid>`。
- **0.16.11**：探索页的年份跟着系统时间走——默认筛选就是「今年」（现在 2026），第一屏不再是各年份混排的老片；年份下拉最新只到今年，不再出现明年这种选了必空的下拉项。「近 N 年」和年代按钮也用同一个年份基准。默认值不占「筛选」按钮的数字，重置回到今年，想看不限就选「不限」。
- **0.16.10**：修 0.16.7 带来的启动即失败——设置页「测试连通性」和「立即刷新库存索引」都会报 `'_MultiAddressHTTPSHandler' object has no attribute '_check_hostname'`。原因是那段连接代码按本机 Python 3.9 写的，而镜像里的 3.12 已经删掉了这个私有属性；现在改为只传 `context`，并在 3.12 容器里实测极影视公网地址返回 200。
- **0.16.9**：设置页把原来的「播放与点播」拆成两个分区——**STRM 设置**（对外访问地址、限频与缓存、扫描后缀名）和 **Seerr 与极影视**（Seerr 点播对接 + 极影视接入）。原来平铺在页面上的长段说明收进字段旁的 `i` 按钮，点开是分节说明；一级界面只留字段名和一行提示。分区总数变成 8 个，序号顺延。
- **0.16.8**：修手机竖屏筛选面板的排版——标题「筛选条件」之前挤在面板边框上（一条旧规则还带着负外边距），往里每层各有一个左缩进，分区是「卡片套卡片」；现在分区不再套卡片、只保留面板一层圆角，标题/小节标题/标签/输入框统一 0.9rem 缩进，快捷年代 chip 改成四列等宽两行。桌面端样式不变。

- **0.15.29**：文件管理勾选栏只留常用操作（重命名、复制、删除、批量整理），移动到…、区间选择、扫描监控、查重收进「更多」菜单；修手机端文件列表被上方横条挤到只剩两三行的问题——先量出横条实际高度再给列表留地板，放不下时面板长高让页面滚动；手机端勾选栏自适应网格一行放下，查重面板最大高度 52vh→40vh。
