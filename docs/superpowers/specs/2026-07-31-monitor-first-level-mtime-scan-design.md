# 文件夹监控首层修改时间校验设计

## 背景

当前“按文件夹修改时间校验”会读取一个目录的全部直接子项，并把最大的 `modified_at` 当作该目录的修改时间。扫描器在进入子项判断前先比较这个汇总时间；只要历史最大值不小于本轮最大值，就会跳过整个目录。

这个模型会漏掉兄弟目录之间的变化。例如 `SeasonB` 的时间是 `12:00`，`SeasonA` 从 `10:00` 更新到 `11:00`，父目录的最大时间仍是 `12:00`，扫描器会跳过父目录，无法看到已经变化的 `SeasonA`。更深层变化如果没有由 115 传播到上层文件夹时间，也无法通过父目录时间可靠发现。

项目的常见目录结构是：监控目录的第一层直接放资源文件，或者每个资源占用一个第一层文件夹。日常监控应固定读取这一层，逐项判断变化；更深层且未向第一层传播的变化，由用户关闭跳过开关后手动完整扫描。

## 目标

- 开启修改时间校验时，每轮固定读取监控根目录第一层。
- 分别判断每个第一层文件和文件夹，不再使用父目录最大时间跳过整个任务。
- 第一层文件夹未变化时跳过整棵子树，减少 115 目录访问。
- 第一层文件夹新增、变化或待补扫时，完整递归扫描该分支，不在分支内部继续按目录时间剪枝。
- 关闭修改时间校验时，完整递归扫描整个监控目录，用于发现未传播到第一层的深层变化和重建 STRM。
- 保留失败补扫、过期 STRM 清理和局部刷新现有安全语义。
- 升级后不复用含义不同的旧时间缓存，避免首次运行错误跳过。

## 非目标

- 不承诺在开启修改时间校验时发现所有未向第一层文件夹传播的深层变化。
- 不新增高频轮询、目录树常驻缓存或独立后台巡检任务。
- 不改变任务的手动、定时、Webhook 和资源导入触发入口。
- 不改变 STRM 地址、写入模式、文件类型和最小文件大小规则。
- 不把当前设计扩展到 115 以外的网盘；文件夹监控运行配置目前只接受 115 路径。

## 用户可见语义

### 开启“按文件夹修改时间校验”

每轮任务至少读取一次监控根目录，并检查根目录中的每个直接子项：

- 第一层视频文件：按现有扩展名和最小大小规则处理，并用路径、修改时间和大小维护本轮文件索引。
- 第一层文件夹：比较该文件夹在根目录列表中返回的自身修改时间和上次成功扫描基线。
- 新文件夹、时间变化的文件夹或包含待补扫记录的文件夹：完整递归扫描该文件夹。
- 时间未变化且没有待补扫记录的文件夹：不访问内部目录，复用已有文件索引。
- 没有可靠修改时间的文件夹：不能安全跳过，完整递归扫描。

根目录永远不再使用“所有子项的最大修改时间”整体跳过。一个第一层文件夹被判定需要扫描后，其内部所有目录都按完整递归方式读取，避免再次被更深层的时间判断截断。

### 关闭“按文件夹修改时间校验”

从监控根目录开始完整递归扫描，不读取或应用任何目录跳过基线。该模式是发现深层未传播变化、手工删除 STRM 后重建、以及排查远端时间异常的明确恢复入口。

关闭开关只影响本次及后续任务的扫描策略，不清空历史状态。完整扫描成功后仍使用本轮根目录列表刷新第一层文件夹基线；重新开启时可以直接使用这份最新基线，避免紧接着再次完整扫描。失败分支继续保留旧基线和待补扫状态。

## 状态模型

### 第一层条目时间

现有 `monitor_dirs.remote_modified` 保存的是“目录内部直接子项的最大修改时间”，不能改名后直接复用为第一层文件夹自身时间。`monitor_dirs` 新增语义明确的字段：

```text
entry_modified TEXT NOT NULL DEFAULT ''
```

该字段只表示：父目录列表中返回的这个文件夹条目自身的 `modified_at`。它不表示目录内部最大时间，也不表示本地文件系统时间。

SQLite 增量迁移只新增空字段，不从旧 `remote_modified` 推导。升级后的第一次运行会因为 `entry_modified` 为空而扫描所有第一层文件夹；每个分支成功后建立新基线。这样会产生一次可预期的完整扫描，但不会继承错误缓存。

`remote_modified` 暂时保留，避免破坏已有数据库和其他诊断数据；新跳过算法不再依赖它。后续确认没有消费者后再单独评估删除，不在本次改动中做破坏性迁移。

### 失败与缺失状态

继续使用：

- `needs_rescan`：目录或其子树上次没有可靠完成，需要强制补扫。
- `missing_confirmations`：第一层目录连续未出现在成功根目录列表中的次数。

只要第一层文件夹自身或其任意后代存在 `needs_rescan=1`，该第一层分支就不能跳过。分支完整成功后才清除相应待补扫状态并保存新的 `entry_modified`；读取失败、中断或最终索引未提交时不得提前写入成功基线。

根目录成功列出后，历史存在但本轮缺失的第一层文件夹进入现有“两次确认”流程：第一次标记待补扫并保留状态；连续第二次仍缺失才释放目录状态。若中途重新出现，清零缺失次数并强制扫描。过期 STRM 是否删除继续服从 `sync_clean` 和“本轮无目录读取失败”的安全条件。

## 扫描流程

### 全任务扫描

1. 读取监控根目录，得到完整第一层条目列表。
2. 处理第一层文件，并写入本轮临时索引 `current_scan`。
3. 对每个第一层文件夹加载 `entry_modified`、`needs_rescan` 和后代待补扫状态。
4. 开启时间校验时，仅当当前时间非空、历史基线非空、两者完全相等且整个子树无待补扫记录，才跳过该文件夹。
5. 跳过时把 `monitor_files` 中该子树的缓存复制到 `current_scan`，避免清理阶段误删。
6. 其余第一层文件夹进入递归队列；该分支内不再执行目录修改时间跳过。
7. 分支成功后保存根目录列表中观察到的第一层 `entry_modified`；失败则保留或设置待补扫。
8. 根目录和所有已进入分支扫描均满足安全条件后，按现有 `sync_clean` 语义清理过期 STRM 并提交文件索引。

时间比较使用“规范化后完全相等”，不再使用 `历史时间 >= 当前时间`。远端时间变小也属于状态变化，应重新扫描，而不是继续跳过。

### Webhook 和资源导入局部刷新

现有 `savepath/sharetitle` 定位到第一层文件夹或其后代时，继续直接扫描目标分支，不先用首层时间挡住明确的刷新请求。局部刷新失败时保留待补扫；后续全任务浅扫描会通过该分支的待补扫状态再次进入。

如果目标路径暂不可见，继续沿用预刷新父目录和回退父目录的逻辑，但回退后只允许进入目标祖先链和目标子树，不扫描无关兄弟目录。

## 清理与异常处理

- 根目录读取失败：任务失败，不更新任何首层成功基线，不执行过期 STRM 清理。
- 某个变化分支读取失败：标记分支待补扫，保留旧基线，不执行本轮过期 STRM 清理。
- 任务中断或异常退出：当前活动分支和本轮已访问但未提交的分支标记待补扫。
- 未变化分支：缓存文件必须进入 `current_scan`，不能因未实际访问而被当作远端删除。
- 第一层目录删除或改名：旧路径走缺失确认，新路径因没有基线执行完整扫描。
- 第一层文件删除或改名：根目录列表能够直接反映，按现有 `sync_clean` 条件清理旧 STRM。
- 第一层文件夹时间为空：每次完整扫描该分支，以正确性优先。

## 界面说明

复选框名称保持“按文件夹修改时间校验（未变化目录跳过更新）”，帮助文案改为明确边界：

> 开启后，每次读取监控目录第一层，只深入扫描新增、发生变化或待补扫的第一层文件夹。更深层变化若没有同步更新第一层文件夹时间，可能无法自动发现；需要关闭本开关后手动运行一次完整扫描。读取失败的目录会自动保留待补扫状态。

任务日志继续显示“目录时间检查：开启/关闭”，并补充首层扫描结果：扫描分支数、跳过首层文件夹数和待补扫分支数。无需增加新的任务开关。

## 测试与验证

后端回归测试至少覆盖：

- 父目录最大时间不变，但其中一个第一层文件夹时间变化时，只扫描变化分支。
- 多个第一层文件夹中，未变化分支不产生目录列表请求，变化分支完整递归扫描。
- 变化分支内部的第二层目录时间未变化时，仍然继续完整扫描，不应用深层剪枝。
- 第一层直接视频文件新增、保留、改名和删除的索引与清理行为。
- `entry_modified` 迁移后为空时执行一次完整扫描，成功后建立基线，第二次才允许跳过。
- 第一层文件夹没有修改时间时不能跳过。
- 远端时间变小仍被视为变化。
- 子树存在 `needs_rescan` 时覆盖时间相等判断；成功后清除，失败或中断后保留。
- 第一层目录短暂缺失、重新出现及连续两次确认缺失的状态释放。
- 开关关闭时完整递归扫描全部分支，并能发现测试中刻意不传播到第一层的深层变化。
- 跳过分支缓存进入 `current_scan`，开启 `sync_clean` 时不会误删；有读取失败时继续禁止过期清理。
- Webhook/资源导入局部刷新不被首层时间基线拦截。

验证命令遵循项目约定：完整 Python `unittest`、项目 `compileall`、改动 JavaScript 的 `node --check` 和 `git diff --check`。界面文案修改后，在日间和夜间主题下确认监控弹窗文字可读且移动端不溢出。

## 验收标准

- 日常开启时间校验时，每个任务固定访问根目录一次，未变化第一层文件夹不再产生递归目录请求。
- 任一第一层文件夹时间变化时，不受其他兄弟目录时间大小影响，能够扫描并更新对应 STRM。
- 变化分支一旦进入扫描，其内部不再发生基于目录时间的跳过。
- 关闭开关并手动运行后，能够完整访问整个监控目录并恢复深层遗漏。
- 升级后的旧缓存不会直接触发跳过，失败和中断不会写入虚假的成功基线。
- 开启过期清理时，跳过、失败、缺失和局部刷新场景均不发生越界或误删。
