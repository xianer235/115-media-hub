# 大爆炸选词原文标点保留设计

## 背景

应用级 `MediaHubTextSelection` 已被 ED2K 新建文件夹和刮削识别共同复用，但旧模块只生成中文、英文和数字词块。首次标点保留实现能够在完成选词时按原文位置恢复标点，却没有把实际会进入结果的标点显示成独立选词框，造成选择过程和最终结果不一致。

这会把 `碟中谍：最终清算 (2025)` 拼成 `碟中谍最终清算 2025`，也会把 `摇滚兄弟私生活 (2024) - S03` 拼成 `摇滚兄弟私生活 2024 S03`。问题属于共享选词模块，而不是 ED2K 或刮削页各自的界面问题。

## 目标

- 保持完全手动选词，不自动预选、猜测标题、删除集数或生成标准名称。
- ED2K 与刮削页继续复用同一个选词模块，并获得一致的标点还原行为。
- 冒号、括号、方括号、点号和连接符等合法标点与文字一样显示为独立可选词块。
- 完成结果只包含用户实际选择的文字和标点词块，保持所见即所得。
- 路径分隔符不进入搜索词或文件夹名称。
- ED2K 提交时继续执行文件夹名称安全处理，但不再无提示地丢失可保留标点。

## 非目标

- 不接入 TMDB 自动识别或自动生成电影、电视剧文件夹名称。
- 不自动把 `S03E01-E08` 收敛为 `S03`。
- 不改变大爆炸的点击、滑动选择、清空、收起和重新选词交互。
- 不改变刮削页搜索、媒体类型选择、结果绑定或标准命名流程。
- 不改变 ED2K 文件选择、目标目录选择或批量任务结构。

## 共享模块设计

`MediaHubTextSelection.tokenize()` 生成三类可点击词块，并保留每个词块在原文中的起止位置：

- 单个中日韩统一表意文字。
- 连续英文字母和数字。
- 单个合法标点或普通符号，例如 `： ( ) [ ] . - · & +`。

空白、路径分隔符 `/` 和 `\`、表情符号及 `* ? " < > |` 不生成词块。路径分隔符仍只负责划分原始路径，ED2K 不安全字符继续由文件夹名称规范化层处理。

`MediaHubTextSelection.compose()` 调整为按以下规则组合：

1. 将已选词块索引排序并划分为一个或多个连续区间。
2. 每个连续区间只按顺序拼接实际选中的词块；原文空白只贡献一个间隔，`/` 和 `\` 作为路径结构也转换为一个空格。
3. 标点本身是词块，不执行边界标点或括号的隐藏补全；未生成词块的表情和不安全字符也不能从原文间隙回流。
4. 多个不连续区间分别组合，再用一个空格连接；被跳过的文字和标点不会混入结果。
5. 最终连续空白收敛为一个空格。

该规则保留冒号、括号、方括号、独立短横线、长横线、句点、间隔号、撇号、与号、加号、逗号、感叹号等原文标点。它不根据标点内容推断影视类型或媒体信息。

## 组合示例

| 原文 | 手动选择 | 结果 |
| --- | --- | --- |
| `🎬 电影：寒战1994 (2026)` | `寒战1994`、`(`、`2026`、`)` | `寒战1994 (2026)` |
| `碟中谍：最终清算 (2025)` | 全部标题与年份 | `碟中谍：最终清算 (2025)` |
| `📺 电视剧：摇滚兄弟私生活 (2024) - S03E01-E08(完结)` | 标题到季集范围 | `摇滚兄弟私生活 (2024) - S03E01-E08` |
| `电视剧/欧美/S.W.A.T. (2017)` | 跨目录连续选择 | `电视剧 欧美 S.W.A.T. (2017)` |
| `标题 (2024) [tmdbid-123]` | 只选 `2024` | `2024` |
| `标题 (2024) [tmdbid-123]` | 选择 `[` 到 `]` 的完整区间 | `[tmdbid-123]` |

## 消费方行为

### ED2K 新建文件夹

`ResourceEd2kImport.composeFolderName()` 继续作为兼容入口，但直接复用共享模块的新组合结果。完成选词后，结果写入现有文件夹名称输入框，用户仍可手工修改。

提交接口对文件夹名称执行最终安全规范化：

- 删除控制字符并收敛多余空白。
- `/` 和 `\` 转为空格，避免形成额外路径层级。
- 保留冒号、括号、方括号及普通标题标点。
- 对可能影响跨平台 STRM 落盘的字符执行固定映射：`*` -> `＊`、`?` -> `？`、`"` -> `＂`、`<` -> `＜`、`>` -> `＞`、`|` -> `｜`，不直接删除。
- 保留现有空名称、`.`、`..` 和长度限制校验。

文件夹安全规范化由 `ResourceEd2kImport` 提供前端纯函数。完成选词和最终提交前均调用该函数；提交前若名称发生变化，先把规范化结果回写输入框，再发送请求。后端使用同一组确定规则做防御性复核，并在响应中返回实际文件夹名称。前后端测试复用同一组输入与预期结果，防止规则漂移。

共享选择模块只负责还原标题；文件夹安全规范化属于 ED2K 消费层，不进入刮削搜索词。

### 刮削识别

刮削路径选词继续直接调用 `MediaHubTextSelection.compose()`。完成选词后，带有原文标点的结果写入 TMDB 搜索框。搜索框仍允许手工修改，重新展开选词时也不覆盖用户后续编辑，直到再次点击完成选词。

完整路径中的 `/` 和 `\` 会变成空格，因此跨目录选择不会生成路径式搜索词。

## 边界与错误处理

- 没有选中任何词块时，沿用现有不可完成和提示行为。
- 括号、冒号和横线必须作为独立词块被选中才进入结果，不执行隐藏补全。
- 不连续选择不会保留跨越未选词块的文字或标点。
- 标题中的表情符号和不安全字符不生成词块，也不会从相邻已选词块之间自动进入结果。
- 手工编辑后的 ED2K 文件夹名称仍需经过同一后端安全规范化，不能绕过路径与控制字符校验。

## 测试与验证

- 扩充共享前端逻辑测试，覆盖中英文冒号、圆括号、方括号、独立横线、点号、撇号及不连续选择。
- 覆盖合法标点独立分词、单独选择和连续拖选，确认未选标点不会进入结果。
- 覆盖完整路径 `/`、`\` 转空格，确认不会生成额外路径层级。
- 回归 ED2K 文件夹拼接，确认完成选词、手工编辑和提交后的名称一致。
- 回归刮削路径选词，确认共享标点规则生效且搜索框手工编辑行为不变。
- 使用同一组契约样例测试前后端文件夹安全规范化，覆盖冒号保留、危险字符全角替换、控制字符、空名称和长度限制。
- 执行完整 Python unittest、项目 `compileall`、所有改动 JavaScript 的 `node --check` 和 `git diff --check`。
- 使用内置浏览器分别在桌面和 `390x844` 视口验证 ED2K 与刮削页的点击、连续滑动、重新选词、日夜主题和无横向溢出。
