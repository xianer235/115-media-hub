# 刮削操作驱动的精准 STRM 同步设计

## 背景

刮削管理和文件夹监控原先各自维护状态。用户在刮削页对 115 文件执行重命名、复制、移动、删除或新建文件夹后，监控索引和本地 STRM 不知道远端已经发生变化，只能再次执行一次全量或局部监控扫描才能收敛。对大目录来说，这会产生不必要的 115 列目录请求，也让操作结果和本地媒体库之间出现可见延迟。

本设计把刮削操作的已知路径变化变成持久化事件。网盘执行层仍使用条目 ID 调用 115 接口；网盘动作确认成功后，文件夹监控层只使用刮削动作已经掌握的完整旧路径、完整新路径和现有监控索引，不接收或解释父目录 ID，也不读取监控根目录或目标子树。未知文件夹由用户后续手动监控补齐。

## 目标与边界

- 115 刮削操作成功后，按旧路径和新路径命中所有覆盖路径的监控任务，并精确更新 STRM 与 `monitor_files`。
- 批量动作的 `old_path/new_path` 始终保存为 115 挂载点下完整路径；`target_parent_path` 只用于远端执行。旧待执行任务依据已保存的 `base_path` 确定性补全路径。
- 远端调用前持久化 `prepared` 事件；调用失败的刮削事件直接结束，不进入本地同步。进程中断或启动恢复等远端结果未确认的非刮削事件仍可进入局部校正。
- 变更事件通过独立的 `change` 监控队列处理，并与普通扫描串行；变更处理不进入普通扫描 walker。
- 文件夹操作优先复用所有覆盖监控任务的现有文件和目录索引；索引未知时只同步已知部分，不列目标子树，并标记 `manual_required`。
- 继续遵守扩展名和最小文件大小过滤。显式删除只删除事件明确指向的 STRM，不受 `sync_clean` 影响；`strm_write_mode=full` 不改变精确事件。
- 完整事件直接迁移或克隆 `monitor_files`、`monitor_dirs` 基线，并保持 `needs_rescan=0`，避免下一次普通监控被强制复扫。
- 手动监控会让 `manual_required` 对应的一级分支绕过目录时间跳过；只有本轮实际成功覆盖的事件才清除提示。
- 仅 115 生成事件；夸克、阿里、天翼和 123 等其他网盘保留原文件管理行为，并返回 `not_applicable` 同步状态。

不在本设计中实现原地修改 STRM 内容、恢复本次修复前已受影响的历史 STRM、扩大到整个监控根目录的兜底扫描，或新的独立监控页面。

## 组件与数据模型

### 持久化事件

`monitor_change_events` 是独立于 `monitor_files` 和 `monitor_dirs` 的事件表。每一条事件按监控任务拆分，保存：

- `operation`：`create`、`copy`、`move`、`rename`、`delete`；
- `old_path`、`new_path`：115 挂载点下的相对路径；
- `entry_snapshot_json`：名称、父路径、类型、大小和修改时间，以及已知文件夹清单；远端结果未确认的普通事件才额外保存用于局部校正的条目/父目录 ID，刮削任务的已确认路径事件不保存这些 ID；
- `task_name`、`source_action`、`dedupe_key`：来源和批量动作去重信息；
- `status`：`prepared`、`pending`、`processing`、`completed`、`manual_required`、`failed`；
- `needs_reconcile`、`retry_count`、`next_retry_at`、`last_error`；
- 目录/文件处理统计和创建、确认、完成时间。

唯一键是 `dedupe_key + task_name + old_path + new_path`。直接操作使用请求序号；批量刮削使用“任务 ID + 动作 ID + forward/rollback”，因此执行和回退可以安全重放。连续路径合并以监控任务、连续路径和显式条目 ID 为身份，不把 `source_action` 文本当作条目身份；若尚未本地执行的链路回到原路径，则两条事件收敛为无操作完成。

### 状态流转

```text
             115 调用成功
prepared --------------------> pending
   |                             |
   | 调用失败/启动恢复            | 处理器领取
   v                             v
pending (needs_reconcile=1) -> processing
                                  |
                         +--------+-----------------+
                         |        |                 |
                      completed  manual_required  failed
                                  |          (退避重试，保留事件)
                       手动扫描实际成功覆盖
                                  |
                              completed
```

启动恢复时，普通 `prepared` 事件转为 `pending + needs_reconcile=1`；若 create/copy 文件夹快照已保存经过校验的目标 CID，则视为远端结果已确认，直接保持精准处理。`processing` 事件保留原有 `needs_reconcile`，并在快照中标记 `local_sync_uncertain`；该标记阻止后续 forward/rollback 链被折叠成无操作，必须按事件顺序重放本地变更，避免数据库回滚而 STRM 已部分写入时丢失修复机会。刮削任务已经确认成功的路径同步如果失败，则恢复本次本地文件 journal、写入监控日志并删除事件，不累计重试次数，也不进入任务卡计数。普通监控变更仍保留原有重试机制。

## 事件产生与路径匹配

刮削页的重命名、复制、移动、删除和新建文件夹请求增加可选快照和 `request_id`。缺少快照的旧客户端仍先执行原网盘操作，但返回 `monitor_sync.status=unavailable`，不猜测路径。快照不完整时只创建能够安全定位的事件；无匹配监控任务返回 `not_matched`。

请求中的 `entry_id/entry_ids` 是网盘执行层的权威条目集合。快照必须携带与请求一致的显式 `id/cid/fid` 才能执行网盘操作，不按数组位置补猜 ID，也不使用混入选择列表的旧条目。网盘动作确认成功后，传给文件夹监控的事件只保留文件名和完整旧、新路径；重命名快照 ID 不一致、删除或移动快照不属于请求集合时，网盘操作保持兼容，但相应条目不创建同步事件。

准备阶段对旧路径、新路径分别匹配所有覆盖它们的监控任务，去重任务名后为每个任务插入事件。对于文件夹旧路径，先从所有匹配任务的 `monitor_files` 和 `monitor_dirs` 捕获共享索引清单；该清单随事件快照保存，使跨监控任务移动和已有索引复制无需再次列目录。连续文件夹改名或移动合并时，文件清单、目录基线和 `manual_required` 状态一并继承。

批量刮削执行和回退复用同一事件生命周期。计划生成时把当前目录与动作相对目录拼成完整 `old_path/new_path`，任务落库时同时保存 `base_path`；兼容旧待执行任务时只依据该 `base_path` 补全，不猜测网盘结构。执行时用已成功的父目录路径变换重写后续子项的当前路径；文件夹监控收到确认事件后统一按旧路径到新路径的投影处理，不再依据父目录 ID 重新区分 rename/move。回退按相反顺序保留尚未回退的父目录映射，先在当前目录内恢复子项，再恢复父目录名。同一批后续文件夹事件捕获索引清单时，会先投影此前已确认的子项路径变化，避免用旧文件名覆盖已处理结果；消费旧版遗留事件时也只根据同批已完成的父目录事件恢复当前路径。事件去重键区分正向和回退，避免两次动作互相覆盖。旧、新路径完全相同的动作直接跳过，不创建无意义的监控事件。

## 精确处理器

### 文件

- 执行前先为每个监控任务构建并校验 `delete/add/replace/noop` 计划。确认成功的 rename/move 只依据完整旧路径和完整新路径确定本地变换，不校验父目录 ID；路径不完整、越界或不属于监控范围时不修改旧 STRM。
- 删除或移出监控范围：删除对应任务的 `monitor_files` 行；仅当没有其他监控任务继续引用同一个 `local_rel_path` 时才删除物理 `.strm`，全程不读取 115 目录。
- 新增、复制或移入：按新路径和快照元数据生成 STRM，并 `INSERT OR REPLACE` 索引。
- 重命名或移动：校验通过后先删除旧 STRM/索引，再按新路径生成；不修改原文件内容，也不清理文件级操作留下的空目录。
- 扩展名或大小不符合任务过滤时不生成 STRM，但仍完成事件和基线更新。
- 所有文件夹索引条目逐项验证旧根目录包含关系、目标路径包含关系和任务监控范围；清单中任何无效、重复或越界路径都会在删除前使整个事件失败。
- 目标任务的 `manifest_known` 由来源任务的过滤范围决定：来源索引必须是干净且最小文件大小阈值不高于目标任务，不能用任一任务的“完整”状态覆盖过滤更宽的任务。
- 共享物理 STRM 只有在所有监控索引指向同一远端 URL 时才允许写入；不同 URL 的引用冲突会在本地变更前失败并重试。文件系统写入使用事件级 journal，数据库或任一 STRM 操作失败时恢复原文件内容。

### 文件夹

- 删除旧路径时以 `monitor_files` 的路径前缀删除索引和 STRM；只操作托管的 `.strm`，字幕、NFO、海报等文件保持不变。
- 已知索引的复制、重命名和移动使用保存的文件清单和目录基线重建，不列远端目录。
- 索引未知或存在脏范围时，仍同步能够确认的已有索引部分，但不读取新文件夹子树；事件完成本地部分后转为 `manual_required`。
- 精确处理完成后，旧目录状态被删除，新目录状态按保存基线迁移或克隆，新增目录写入干净基线，均不设置 `needs_rescan`。
- 未确认删除若按条目 ID 找到同一文件但名称已变化，也按删旧/建新替换索引；名称未变化则保持现有索引，不重复写 STRM。

### 手动补齐

手动运行监控前读取该任务的 `manual_required` 事件，并将每个目标映射到监控根下的一级分支。这些分支即使 `entry_modified` 未变化也必须进入递归扫描，但不会为了强制进入而预先持久化 `needs_rescan=1`。扫描结束后按本轮开始时捕获的事件 ID 清除提示：目标一级分支必须完整扫描成功；某个分支或其后代读取失败时只保留该分支的提示，其他成功分支可以正常完成。若根目录确认目标一级分支已不存在，也视为该范围已覆盖。

### 局部校正

局部校正仅用于远端结果未确认的事件，并且只读取一次受影响条目的父目录。快照带显式条目 ID 时只接受相同 ID 的远端条目，不使用同名但不同 ID 的文件兜底；确认到同一 ID 后仍按远端实际名称重建索引。未确认删除若找到同一条目但名称已变化，也按删旧/建新替换索引；名称未变化则保持现有索引。文件夹删除若被确认成同 ID 改名，且旧索引带有脏范围或没有完整清单，迁移已知索引后仍保留 `manual_required`，等待用户手动监控补齐未知内容。创建或复制事件在目标父目录内找不到目标条目时进入退避失败并保留。直接位于监控根目录的文件不会通过列根目录来兜底；无法在局部边界内确认时保留失败事件，绝不扩展为监控根目录或目标子树扫描。

## 队列、恢复与保留

监控队列条目带 `mode=scan|change`。同一任务的普通扫描和变更同步不会合并，队列执行器保持全局串行；变更模式只消费持久化事件。队列锁同时保护“dispatcher 已安排、worker 尚未接管”的保留状态，空闲时连续入队只会创建一条调度链；任务不存在或配置错误的早退分支也会释放保留并继续下一任务。刮削任务确认成功后产生的本地路径同步是一次性消费：失败只写日志并删除事件。其他来源或需要局部校正的监控事件仍最多自动重试 5 次，采用 5 秒起的指数退避。

`completed` 事件保留 30 天后清理；`pending`、`processing`、`manual_required` 和普通 `failed` 事件按既有规则保留。刮削路径同步失败事件不保留。监控状态接口按任务返回待同步、普通失败和需手动监控数量；刮削路径同步失败只出现在变更处理日志中。

## 接口状态

成功的刮削操作响应保留原字段并增加：

```json
{
  "monitor_sync": {
    "status": "queued",
    "matched_tasks": ["影视监控"],
    "event_count": 1,
    "event_ids": [42]
  }
}
```

状态可能是 `not_applicable`、`unavailable`、`not_matched`、`queued`、`reconcile_queued`、`processing`、`completed`、`manual_required` 或 `failed`。刮削提示会明确说明“STRM 将同步已知内容，完成后需手动监控补齐”，监控任务卡显示对应计数，不增加独立页面。
