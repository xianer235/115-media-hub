# 文件夹监控日志可读性优化方案

日期：2026-08-25

## 背景与目标

用户日常阅读文件夹监控日志不够直观。现状问题：

1. 触发原因和扫描范围在“任务开始”之后才出现（定位/范围行在正文中段），结束行只有状态，需上下翻找。
2. 动作没有统一视觉前缀，长日志难以扫读（生成/跳过/清理/失败全靠文字区分）。
3. 术语不统一：“跳过文件 / 跳过目录 / 跳过文件夹”“深扫分支 / 待补扫分支”“局部读取目录”含义接近但叫法不同。
4. 阶段边界只有 `·· 扫描生成 ··` 这类纯文本分隔，视觉弱。

目标：在不改变日志数据模型、不破坏前端既有解析（task-divider 正则、level 类、汇总行装饰）的前提下，让监控日志“一眼可读”。

## 设计原则

1. **后端补信息，前端做视觉**：后端只新增“缺失的信息”（范围行、结论行），已有文案尽量不动，避免破坏持久化日志与测试断言。
2. **视觉增强放前端**：按前缀装饰 + 图标 + 颜色，历史日志（旧文案）不匹配时原样显示，无兼容风险。
3. **可选项不强行做**：术语统一收益低、风险高（要改文案与断言），默认不做，只做前端装饰。

## 改动清单

### A. 后端（app/services/monitor.py）

1. **任务开始后新增“范围”行**（紧跟任务头三行之后）：
   - 资源导入 / Webhook：`范围: {定位到的目录}`（hinted_path）
   - 指定目录扫描：`范围: {savepaths 列表}`
   - 手动强制补扫：`范围: 需补扫首层分支`
   - 无定位（回退全任务）：`范围: 全任务 {scan_path}`
   - 实现为纯函数 `build_monitor_scope_line(task, trigger, payload, hinted_path, resolved_paths)`，便于单测。
2. **执行成功前新增“结论”行**（footer 前，自动整理之后）：
   `结论: 新增/更新 {generated} | 跳过 {skipped} | 自动整理 {N} 项 | 清理 {deleted_files}`
   - 自动整理结果改为变量 `auto_message`，结论行复用其中的“已自动整理 N 项”摘要；未开启或失败时对应位置显示 `-`。
   - 失败/中断路径不输出结论（已有“失败原因”行）。
3. **变更同步保持不变**（已有“变更同步汇总”足够），不新增结论，避免冗余。

### B. 前端（static/js/index.js 日志渲染）

1. 将现有 `decorateMonitorSummaryText` 扩展为通用装饰 `decorateMonitorLogText`，按前缀匹配并输出带图标/色的 HTML：
   - `读取目录:` → `📁` + 弱化路径
   - `生成:` / `生成 STRM:` → 绿色 `＋`
   - `跳过` → 灰 `⏭`
   - `清理` → 灰 `🧹`
   - `自动整理:` → 蓝 `⟳`
   - `已自动安排补扫目录` → 蓝提示
   - `范围:` / `定位刷新目录` → 蓝 `➜`
   - `失败原因|失败|错误` → 红 `✕`
2. 扩展汇总行装饰到 `首层汇总:`、`变更同步汇总:`（复用 `decorateSummaryMetric`，不重构）。
3. task-divider 解析、level 类、色调逻辑保持不变。

### C. 测试

1. 后端：新增 `build_monitor_scope_line` / 结论行纯函数单测（四种触发场景 + 无定位回退 + 自动整理摘要复用）。
2. 前端：新增 VM 回归（参照 tests/test_subscription_ui_frontend.py 模式），断言各类前缀返回含图标/类名的 HTML、旧文案原样输出。
3. 若 A 中不改任何既有文案，现有断言全部保持。

### D. 验证

全量 unittest、compileall、改动 JS `node --check`、`git diff --check`；Docker 重建后浏览器实测日/夜模式可读性与历史日志兼容。

## 风险与兼容

1. 前端按前缀装饰 → 日志全部由系统生成，无用户自定义文案，误伤风险低；不匹配时原样显示。
2. 装饰不落库，只影响展示，持久化日志保持纯文本。
3. 不改 divider 格式与 level 模型 → 现有解析与色调不受影响。
4. 结论行只在成功路径输出 → 不影响失败/中断流程。

## 自审意见（一次审查）

- 原计划中的“术语统一（深扫分支等）”被**砍掉**：收益低、要改文案与断言，改为前端视觉区分，范围更小。
- “结论”行与“生成汇总”有信息重叠，但定位不同（结论=一句话可读，汇总=明细），保留并精简为 4 个指标。
- 前端装饰函数扩展复用现有 `decorateSummaryMetric`，不重构，避免回归。
- 范围行四种触发场景取值已定义，含“无定位回退全任务”兜底。

## 实施顺序

1. 后端：范围行 + 结论行（含自动整理结果变量）。
2. 前端：装饰函数扩展 + 图标。
3. 测试：后端纯函数单测 + 前端 VM 回归。
4. 全量验证 + handoff 记录。
