# 多网盘资源互传可行性研究

日期：2026-08-25

## 背景与目标

用户希望在 115 / 夸克 / 天翼云盘 / 123 云盘 / 阿里云盘之间实现资源互传，并借助"影视订阅扫描链接"自动完成跨网盘入库，替代手动下载再上传。本文记录调研结论、可行性与分期建议，并标注当前已实现/未实现状态。

## 现状盘点（代码侧）

五个网盘均有 `CloudProvider` 实现（`app/providers/`），能力声明如下：

| 网盘 | 分享转存 | 文件夹操作 | 离线下载 | STRM/监控 |
|---|---|---|---|---|
| 115 | ✅ | 重命名/移动/复制/删除 | ✅ 磁力/ed2k/HTTP | ✅ |
| 夸克 | ✅ | 重命名/移动/复制/删除 | ❌ | ❌ |
| 天翼 | ✅ | 重命名/移动/复制/删除 | ❌ | ❌ |
| 123 | ✅ | 重命名/移动/删除（无复制） | ❌（账号密码链路不支持磁力） | ❌ |
| 阿里 | ✅ | 重命名/移动/复制/删除 | ❌ | ❌ |

关键缺口：所有 `resolve_download_url` 未实现；目标盘上传均未实现（123 的 `upload_request` 只用于建文件夹）；scraper 的复制/移动仅限同盘。

## 问题一：跨盘秒传

各网盘自身秒传机制：

| 网盘 | 秒传所需哈希 | 备注 |
|---|---|---|
| 115 | SHA1 + size + 签名 | 服务端可能再校验文件某字节段 SHA1 |
| 阿里云盘 | SHA1（content_hash_name=sha1）+ proof_code | pre_hash 前 1KB 预检 |
| 天翼云盘 | 整文件 MD5 | checkTransSecond |
| 123 云盘 | 整文件 MD5（etag） | upload_request 返回 reuse=true 即秒传 |
| 夸克 | md5 + sha1 双哈希 | 社区反馈接口已失效/不可信 |

跨盘秒传的本质：**目标盘必须已存在同哈希文件**，否则秒传失败回退普通上传。由于各盘哈希体系不同，只有哈希可直接复用的组合才有真实价值。

已被 Alist 生产验证的跨盘秒传矩阵（v3.29 官方文档）：

- 阿里云盘 ↔ 115：✅ 双向（均用 SHA1）；
- 天翼云盘 ↔ 百度：✅（MD5 体系）；
- 夸克、123 与 115/阿里之间：❌ 不参与跨盘秒传。

**结论**：本项目只对 115 ↔ 阿里云盘 保留"秒传尝试"作为加速选项（哈希已知时先试秒传，失败自动走流式传输）；其余组合直接走互传。秒传不可保证成功，只能当优化。

## 问题二：不秒传时的传输方式

推荐**流式中转**（Alist 同款架构）：

```
源盘 resolve_download_url（可 Range 的下载链接）
  → SeekableStream（分块读取，支持 Range）
  → 目标盘分片上传（115 OSS / 阿里 part / 123 S3 / 夸克分片 / 天翼分片）
  ↑ 秒传尝试只需读取前 1KB / 指定字节段
```

- 本地临时文件仅作兜底：源链接不支持 Range、或目标盘强制整文件哈希（MD5）时使用。
- 瓶颈是用户本机带宽；大文件上行慢时传输慢，后续可考虑"服务器中转"选项。
- 落地成本：每个源盘补 `resolve_download_url`，每个目标盘补分片上传（均为逆向接口，需持续维护）。

## 问题三：订阅选择文件 + 自动转存/互传

- **同盘**：已是现状——订阅扫描到 A 盘分享链接 → 文件/剧集选择 → 精细转存到 A 盘监控目录 → 自动入库（STRM + 自动刮削）。替代手动下载上传已成立。
- **跨盘**：订阅候选是 A 盘分享、目标库在 B 盘时，推荐"先转存到 A 盘用户目录，再排 A→B 互传任务"（简单、复用现有转存与去重逻辑）；完成后触发 B 盘监控/STRM。依赖问题二的互传基础设施。

## 问题四：磁力链接 → 115 云下载 → 识别挑选入库

**已实现（P0，2026-08-25）**：

- 入口：115 订阅任务"扫描链接"弹窗接受一次性磁力/电驴（不持久化到任务配置）；
- 流程：提交 115 离线到 `云下载/磁力中转/<任务名>/`（根目录可配 `magnet_staging_root`）→ 轮询完成（哈希+目录匹配、可取消、12 小时超时）→ 递归列中转目录 → 复用订阅剧集/标题/质量筛选 → 同名同大小去重后移动命中文件到订阅 savepath → 精准触发监控刷新（STRM + 自动刮削）→ 垃圾文件删除、未命中保留 7 天；
- 定期清理：`subscription_offline_cleanup.py` 每 30 分钟清理中转目录（跳过运行中离线任务；删垃圾/过期、清空目录）。

明确不做：搜索自动发现的磁力不路由；磁力不持久化到订阅任务配置。

## 分期建议

- P0：订阅磁力/电驴 → 115 离线 → 识别挑选入库（**已完成**，待 Docker/真实账号复测）。
- P1：跨盘互传基础设施 v1——115 源/目标的上传与下载解析、流式中转；随后补阿里（获得 115↔阿里 秒传加速）。
- P2：订阅跨盘自动互传（转存 A + Transfer A→B + 目标盘入库）。
- P3：按需补 123/夸克/天翼 上传实现与离线扩展（夸克秒传不建议做）。

## 风险

- 各盘接口多为逆向/非官方（阿里 Open API、123 部分官方接口除外），需持续维护；
- 秒传依赖目标盘已有同哈希文件，不保证成功；
- 流式中转占用本机带宽，大文件任务需要分片断点续传设计；
- 跨盘互传（P1 起）尚未实现，本文为可行性结论与设计基线。
